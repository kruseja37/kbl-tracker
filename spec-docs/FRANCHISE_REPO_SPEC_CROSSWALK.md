## 1. Executive Summary

### Overall implementation picture

The repo has a real franchise foundation, not just screens: franchise creation, copied franchise-owned player/team storage, schedule storage, GameTracker launch, event logging, active-game persistence, completed-game archive, season aggregation, standings, playoffs, offseason state, selected offseason mutations, farm storage/movement, Phase 11 validation/actions, season transition journals, and Almanac queries are present and wired.

The biggest pattern is uneven depth. Mode 2 core gameplay and persistence are materially stronger than Mode 1 import/setup details and Mode 3 mutation systems. The repo often has engines or preview adapters for rich systems, but the franchise UI/storage wiring does not always commit durable franchise state.

### What is strongest

- Franchise save-slot foundation: setup creates a franchise metadata record, copies league/team/player data into franchise-owned storage, tags schedules/stats with franchise identity, and launches franchise home.
- GameTracker foundation: active game identity, at-bat and between-play event logging, undo, autosave/restore, completion, stat aggregation, schedule completion, and archived game detail are wired.
- Regular-season and playoff scaffolding: standings, schedule views, score-game launch, playoff bracket storage, playoff GameTracker launch, series advancement, playoff stats, and leaders have meaningful tests.
- WAR/WPA/manager value foundations: LI/WPA, clutch, manager WPA, mWAR-adjacent systems, and Game Detail audit surfaces are present with test coverage.
- Farm/Phase 11 mechanics: franchise farm records, send-down/call-up actions, option limits, reveal state, Phase 11 validation, and journaled season transition exist.

### What is most incomplete

- Offseason mutation phases are thin outside ratings/salary, selected retirements, and finalization. Free agency, draft, and trade are explicitly preview/read-only. Expansion/contraction, farm reconciliation, and chemistry tabs are guarded or placeholder.
- Relationship/chemistry/personality systems are not franchise-complete. Engines and hooks exist, but franchise relationship data is not clearly loaded from durable franchise storage, and chemistry/farm relationship UI is placeholder.
- Fan morale, player morale, designations, narrative carryover, park factors, adaptive standards, and franchise milestone first/leader persistence are engines or partial consumers rather than complete franchise systems.
- Schedule setup diverges from the spec. The spec requires user-driven CSV/OCR/manual or empty start; repo setup auto-generates a full schedule and only later supports manual add/delete.
- Franchise import is not mutation-capable. Export exists, but `importFranchise` validates a manifest payload and then throws.

### Biggest spec/repo mismatches

- Schedule: spec says user-driven or empty; repo auto-generates schedule on franchise creation via `generateSchedule`.
- Offseason phases: specs disagree on 11 vs 13 phases; repo has a phase state machine but maps some phases to placeholders or unrelated tabs.
- Mutation vs preview: FA/draft/trade have franchise dry-run adapters and visible previews, but no roster/state commits.
- Relationship storage: a storage-backed hook exists under `src/hooks/useRelationshipData.ts`, but franchise data uses `src/src_figma/app/hooks/useRelationshipData.ts`, which is in-memory unless data is manually loaded.
- Milestone storage: milestone detection exists, but `src/utils/franchiseStorage.ts` explicitly stubs franchise first/leader storage.
- Import/export: export is real; import is validate-only.

### Areas where repo is ahead of current v1 needs

- Manager WPA and detailed manager value tracing are deeper than many basic franchise loops require.
- Playoff bracket/stat storage and playoff GameTracker launch are already robust relative to a minimum regular-season loop.
- Several advanced engines exist before their franchise UI/storage is ready: relationship LI modifiers, revenge-game code in prototype trade systems, fan morale engine, park factor deriver, adaptive learning/calibration, HOF/museum-adjacent systems, and fan favorite/albatross engines.
- The synthetic simulation factory exists even though franchise UI access is guarded off.

## 3. Mode 1 Summary

### Complete or mostly complete

- Six-step franchise setup is present and wired.
- Franchise creation copies selected League Builder data into franchise-owned stores and creates metadata/config/schedule/season metadata.
- League Builder has meaningful CRUD coverage for leagues, teams, players, rules, and rosters through `useLeagueBuilderData`.
- Rules, roster assignment, player traits/personality/chemistry/fame/salary fields, and team/stadium fields exist at least as stored/editorial data.
- Franchise startup reaches Mode 2 with a scoped schedule and controlled team metadata.

### Partial or drifted

- Team control supports selected human teams, but exact Solo/Couch Co-Op/Custom semantics and per-team `controlledBy` records are not proven.
- Schedule setup materially diverges: repo auto-generates a schedule during `initializeFranchise`, while the spec asks for CSV/OCR/manual or empty start.
- Franchise import is validate-only even though export is real.
- Player generation/import exists as seed/generator/editor behavior, but hidden modifiers, spec CSV import, and full personality assignment are incomplete.
- Rules presets exist, but complete awards/offseason/AI toggle coverage is not verified.

### Missing or not proven

- Separate abbreviated Playoff Mode franchise creation is not proven, although playoff operation inside a franchise is strong.
- Optional fantasy draft and startup prospect draft are prototype/non-franchise or not proven as setup handoff mutations.
- Complete franchise type phase-scope defaults are not proven.

## 4. Mode 2 Summary

### Regular season / gameplay

Mode 2 gameplay is the strongest implemented area. Franchise Home can launch GameTracker with franchise rosters and identity. GameTracker records at-bats and between-play events, persists active game state, survives refresh, completes scheduled games, aggregates stats, archives completed games, and supports Game Detail/Almanac consumers.

Schedule play is usable for scored games and skipped games. AI simulation exists behind disabled guards, so AI-vs-AI schedule completion is not trustworthy through the normal franchise UI.

### GameTracker / event model

AtBatEvent and BetweenPlayEvent are robust and include WPA/LI, enrichment, edit history/version support, pitcher context, runner context, and pitch-count-related fields. TransactionEvent coverage is partial: selected roster movement, retirement, and Phase 11 actions are journaled, but FA/draft/trade/contract/DFA/IL coverage is incomplete.

### Stats / WAR / WPA / clutch

Stats, season aggregation, leaders, completed-game archive, career/almanac registration, LI/WPA, manager WPA, clutch, and several WAR engines exist. The gap is not basic stat trust; it is full spec breadth: complete five-component WAR persistence/calibration, park-adjusted WAR, full fielding/run value precision, and adaptive standards integration.

### Narrative / reporter / milestones / morale

Narrative infrastructure exists: reporter storage, commentary feed storage, game stories, reporter cache, NewsBoard/Commentary surfaces, and tests. Milestone detection and Fame calculations exist. Fan morale and designations have engines.

The main gap is durable franchise integration. Franchise first/leader storage is stubbed. Fan morale is excluded from persisted summaries. Designations are not proven as a live franchise state with badges/notifications/carryover. Narrative carryover and hidden reporter/player behavior systems are partial.

### Schedule / standings / playoffs

Standings and playoffs are strong. Franchise schedule display, next-game pull, SCORE GAME launch, schedule completion, standings calculation, playoff seeding, bracket storage, playoff GameTracker launch, series advancement, playoff stats, and playoff leaders are implemented and tested.

Gaps include user-driven schedule import/setup, AI simulation availability, trade deadline enforcement, and exact magic/elimination/tiebreak behavior.

### Active-game lifecycle

Active-game save/load/resume is implemented and wired. Current game snapshots, GameTracker identity resolution, autosave/restore, completed-game archive, and Game Detail retrieval all have evidence and tests. This is a trustworthy v1 foundation area.

### Derived / flavor systems

Derived systems are broad but uneven. Manager WPA is deep. Mojo/fitness is game-level. Fan morale, personality hidden modifiers, chemistry, relationships, revenge arcs, park factors, adaptive standards, and rich milestone persistence are partial, preview-only, implemented but not wired, or prototype-only.

## 5. Mode 3 / Offseason Summary

### Phase coverage

The repo has an offseason state machine and visible franchise offseason tabs. The strongest mutation phases are ratings/salary recalculation, selected-player retirement apply, Phase 11 roster validation/actions, and journaled season transition.

Specs conflict on phase count and naming, and repo phase mapping reflects that ambiguity: farm reconciliation and chemistry are Coming Soon, trades map ambiguously, expansion/contraction is a deferred boundary, and spring training is not proven to write franchise state.

### Roster / farm / Phase 11

Farm storage, options, send-down/call-up, rating reveal state, Phase 11 exact 22 MLB/10 farm validation, correction actions, and transition orchestration are present. Team Hub farm analysis is advisory/read-only.

Missing pieces include full farm morale, storylines, warnings, cross-level relationships, draft-round rookie salary lock, complete scouted-only UI, and broad farm mechanical events.

### Retirement / free agency / draft / trade / rating / salary

- Trade: fit preview only; no proposals, acceptance, counter, movement, transaction, morale/chemistry effects.
- Ratings/salary: adapter writes grade/salary, but raw rating changes and full triple-recalc lifecycle are incomplete.
