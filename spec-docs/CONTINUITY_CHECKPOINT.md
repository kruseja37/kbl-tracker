- **F2 (position captured live at Start Draft)** — a player's price freezes at pool lock, but position is re-read fresh when the draft starts; editing a player's position (e.g. closer → starter) in the narrow window after lock but before start could leave the price reflecting the old position while roster legality uses the new one. Needs an unusual out-of-order edit to trigger.
- **F3 (lock→start rating edits reach the tax math)** — the luxury-tax calculation reads player ratings and team tax-identity live, not from anything frozen at lock; normally moot because editing is blocked once a real auction session exists, but in the narrow window between locking the pool and actually starting the draft, a ratings edit could change the tax number the draft opens with.
- **F7 (mutation guard is UI-layer, not storage-layer)** — the "editing is locked while a draft is active" protection lives in page components, not in the underlying save functions; today's three editing pages all carry the guard so there's no live bug, but any FUTURE edit surface (an import tool, a bulk-edit feature) added outside those three pages would silently skip the protection. A storage-layer invariant would close this permanently.
