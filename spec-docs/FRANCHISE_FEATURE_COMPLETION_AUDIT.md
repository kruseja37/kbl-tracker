# Franchise Feature Completion Audit

Date: 2026-05-22

Scope: repo-backed planning audit after the boundary audits, Wave A save-slot lifecycle work, Wave B transition journal work, journal manifest cleanup, and full-suite cleanup. This document does not implement code, does not add roster analyzer work, and does not design the roster analyzer/recommendation engine.

Status legend:

- `complete`: production v1 behavior exists, is scoped, and has focused tests.
- `mostly complete`: production v1 behavior exists with known edge/test debt.
- `partial`: meaningful implementation exists, but important product depth, durability, or tests are incomplete.
- `prototype-only`: UI or engine code exists but is not production-safe for franchise mode.
- `guarded`: intentionally hidden, blocked, or read-only in franchise mode.
- `deferred`: explicitly planned future work with no active v1 production behavior.
- `missing`: required feature has no meaningful implementation yet.

Risk legend: `low`, `medium`, `high`, `critical`.

## Executive Readout

The franchise core is now a boundary-correct Mode 2 v1 loop rather than a pure prototype. Setup, copied franchise-owned roster/team data, scoped schedule rows, regular-season GameTracker launch, standings, playoffs, durable SeasonSummary handoff, transition journals, and manifest-driven export/delete are stable enough for feature work that reads these contracts. The current architecture is the scoped-global hybrid, not the strict two-database model; that decision is documented as intentional in the post-audit roadmap and ADR (`spec-docs/FRANCHISE_IMPLEMENTATION_ROADMAP_POST_AUDIT.md:24`, `spec-docs/FRANCHISE_STORAGE_ARCHITECTURE_DECISION.md`).

The largest product-depth gap is offseason and farm behavior, not identity/scope. Franchise free agency, draft, retirements, trades, expansion, awards ceremony persistence, and full roster lock are still guarded, prototype-only, or partial. Farm storage and durable call-up/send-down writers now exist, but broader UI integration, atomicity, phase context, and roster-lock enforcement are not complete.

Read-only roster analyzer planning is reasonable now if it explicitly treats stats/history inputs as trust-leveled and read-only. Roster analyzer implementation should wait for roster/farm writer hardening, durable roster-lock validation, and a clear decision on whether the analyzer may use deferred career/milestone/flavor data.

## Roster Analyzer Readiness

### Features that truly block roster analyzer planning

No implementation feature is a hard blocker for a read-only planning pass. The platform is ready to plan an analyzer if the planning artifact:

- treats all inputs as read-only;
- lists trust levels for snapshot-derived stats, replay-audited stats, WAR/WPA/clutch, fielding, pitcher decisions, career stats, milestones, morale, and flavor;
- refuses to rely on League Builder globals for franchise-owned recommendations;
- records that career/milestone/fan morale/adaptive/park-factor/fame inputs are not durable franchise history yet;
- avoids designing mutation flows for call-ups, send-downs, trades, signings, draft picks, or roster locks until the movement/adapters are production-safe.

### Features that block roster analyzer implementation

These should be completed or explicitly excluded before any analyzer ships recommendations that users can act on:

- Durable, atomic franchise call-up/send-down writes with repair/rollback diagnostics (`src/utils/franchiseRosterMovement.ts:74`, `src/utils/franchiseRosterMovement.ts:146`).
- Franchise-owned 22/10/32 roster-lock validator and tests (`spec-docs/FARM_SYSTEM_SPEC.md:1708`).
- Clear roster phase context so regular-season and offseason recommendations do not use hardcoded/current wrong-phase assumptions.
- Offseason adapter contracts for free agency, draft, retirements, and trades if the analyzer recommends offseason moves (`src/src_figma/app/components/FreeAgencyFlow.tsx:391`, `src/src_figma/app/components/DraftFlow.tsx:435`, `src/src_figma/app/components/RetirementFlow.tsx:219`, `src/src_figma/app/components/TradeFlow.tsx:135`).
- Canonical career stat and milestone ownership if historical/career achievements affect recommendations (`src/utils/franchiseSaveSlotManifest.ts:335`, `src/utils/franchiseSaveSlotManifest.ts:657`).
- Explicit confidence policy for WAR/WPA/clutch/fielding/pitcher-decision inputs while production aggregation remains snapshot-derived (`src/utils/tests/gameReplayAudit.test.ts:1040`, `spec-docs/FRANCHISE_IMPLEMENTATION_ROADMAP_POST_AUDIT.md:80`).
- Save/export/import policy for analyzer outputs if recommendations are persisted or transferred across devices (`src/utils/franchiseManager.ts:420`).
- Transition journal repair/attention UX if analyzer planning spans season transitions (`src/utils/franchiseTransitionJournal.ts:275`).
